# Evidence-based Superset dashboard specification

This is an analytical specification; no dashboards were implemented. Evidence is the fully read validated generation at `2026-10-12T05:30:05.213076Z`, with subsequent live SQL verification recorded separately in [query_results.json](evidence/query_results.json). All ten new Gold tables are populated in ClickHouse. SQL uses `dsp391m`; substitute the configured database name if needed. All 14 saved queries executed successfully and returned populated results.

**READY** means the stored fields support the stated descriptive question. It does not mean representative national coverage. **PARTIAL** means counts can be displayed with the stated limitation, while broader interpretation is unsupported. **BLOCKED** means the required measurement, reliable source or semantics are missing; no chart implementation is proposed. P0 is the first build, P1 is subsequent analysis, P2 requires stronger evidence.

Global rules: fixed single administrative version/scope; never add NATIONAL to provinces; nullable measures remain NULL; a missing group is unobserved; label counts overlap. Every chart must expose source scope, data freshness, eligibility and time meaning. Keep the latest supply snapshot fixed rather than summing dates. Default social publication range may be October 2026 for a dense sample, but permit the full populated history as a publication inventory. Do not impose that publication filter on collection dates. `generated_at` is source freshness in new tables, not collection date or historical metric time.

The administrative dimension is available in Silver but is not served in ClickHouse. These queries use populated `admin_unit_id` keys. Friendly display labels can use the reference mapping in the EDA evidence; a direct ClickHouse join to a nonexistent administrative dimension, an official choropleth or venue pins is blocked.
